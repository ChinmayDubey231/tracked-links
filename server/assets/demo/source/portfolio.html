01Checkout, rebuilt

Checkout took five screens and lost almost a third of shoppers at payment. I led a three-person team to rebuild it as one screen that loads fast on a cheap phone.

What I did

  • Mapped where people left, using session recordings and funnel data.
  • Prototyped the single screen and tested it with twelve shoppers.
  • Rebuilt it in React and TypeScript behind a feature flag, then rolled it out city by city.

What I learned

The biggest win wasn’t fewer screens. It was showing the delivery fee before payment, so the total never surprised anyone.

Saffron Systems · Customer app2023

02Order tracking, live

Customers phoned support to ask where their groceries were. I built a tracking screen that updates on its own and gives an honest arrival time.

300kcustomers use it each week
−32%“Where is my order?” calls
±6 mintypical error in the arrival estimate
Order placed
Packed
On the way
Arriving
Delivered

Each step updates over a WebSocket; the screen falls back to polling on weak connections.

The problem

The old screen showed a fixed “30–45 minutes” for every order. People didn’t trust it, so they called.

The approach

  • Worked with the data team on an estimate that uses the rider’s live position.
  • Showed a range that narrows as the rider gets closer.
  • Added a calm message when an order runs late, before the customer notices.

Built with

React, TypeScript, WebSockets, and a small state machine so the screen can never show two steps at once.

Accessibility

Status changes are announced to screen readers, and the progress line has a text equivalent.
